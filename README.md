# 系统消息合并 · Single Leading System

SillyTavern 扩展：针对不允许对话中途出现系统消息的聊天模板，按连接与模型选择是否调整消息结构。

> **本插件不是破甲插件，是给自部署的 Qwen3.6 / Qwen3.5 模型做酒馆提示词结构兼容。**
>
> **本插件会在对话中禁用 API 设置中的「提示词后处理」功能，如果与其他预设冲突，请不要使用本插件。**
>
> **本插件不会接管其他插件的提示词注入，如果与其他插件、JS 脚本冲突，请不要使用本插件。**

已提供可安装的扩展入口，代码验证与模拟宿主验证持续进行；实际酒馆和模型联调由用户执行。

## 安装与启用

1. 在酒馆的扩展管理中选择安装扩展，填入仓库地址：`https://github.com/NyaaCaster/st-SingleLeadingSystem`。
2. 在酒馆连接面板选择「聊天补全」，并配置自定义 OpenAI 兼容、OpenAI 或 OpenRouter 的服务地址与模型。Ollama 使用自定义 OpenAI 兼容 `/v1`，不是「文本补全 → Ollama」。
3. 打开扩展设置中的「系统消息合并」，阅读顶部警告，点击「添加当前连接与模型」。
4. 开启插件总开关，并确认该条规则启用。总开关默认关闭，添加规则不会自动打开它。

规则按接口类型、完整地址指纹和模型 ID 匹配。列表只显示协议/主机/端口、地址短编号及备注；路径和查询参数参与匹配但不明文保存。修改模型或地址后需要为新选择添加规则，原规则保留；API 密钥仍由酒馆管理。

更新提醒只检查当前安装分支，不自动安装。打开设置时最多每 24 小时检查一次，也可手动检查；发现更新后在酒馆扩展管理中更新并刷新页面。ZIP 安装可能无法检查更新。

## 确定的行为

- 恢复酒馆的两种示例对白角色，然后合并开头连续的 `system`。
- 中途 `system` 在原位置改为独立 `user`，因此失去系统角色优先级。其他消息的顺序、工具调用、附件及思考字段保留。
- 仅针对启用规则的聊天补全请求。支持自定义 OpenAI 兼容（Ollama 使用 `/v1`）、OpenAI（含反向代理）、OpenRouter。
- 转换成功时，仅关闭**本次请求**的可选提示词后处理，不修改已保存的 API 设置。
- 不支持的消息格式或冲突会整次跳过转换并提示，酒馆继续原流程；原请求仍可能报模型错误。
- 不控制 thinking、预算或截断恢复，不接管工具执行，不支持文本补全路径。

设计参考 Qwen3.6-35B-A3B / Qwen3.5-35B-A3B 官方模板约束，实际酒馆与模型测试由使用者确认，不代表整个模型家族已通过实测。

## 开发验证

源码审计基线为 SillyTavern 1.19.0（`06bde939fb1e9c4c8d8641d810f0a916b5bce127`），不代表所有旧版或第三方分支都兼容。插件会检查所需事件和宿主能力，缺失时停用并提示。其他扩展在本插件之后修改请求，仍可能改变结果。

Node.js 20 或更新版本，运行 `npm ci` 后执行 `npm test`。YAML 仅作为开发测试依赖；实际插件复用酒馆自带的库。运行时使用原生 ES modules，不需要构建或安装 npm 依赖。设计和内部交接文档保存在本地 `.docs/`，不进入 Git。
