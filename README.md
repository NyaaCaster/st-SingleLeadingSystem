# 系统消息合并 · Single Leading System

SillyTavern 扩展：针对不允许对话中途出现系统消息的聊天模板，按连接与模型选择是否调整消息结构。

> **本插件会在对话中禁用 API 设置中的「提示词后处理」功能，如果与其他预设冲突，请不要使用本插件。**
>
> **本插件不会接管其他插件的提示词注入，如果与其他插件、JS 脚本冲突，请不要使用本插件。**

当前处于分阶段开发。核心转换与规则匹配已建立；安装入口和使用说明随完整扩展交付。

## 确定的行为

- 恢复酒馆的两种示例对白角色，然后合并开头连续的 `system`。
- 中途 `system` 在原位置改为独立 `user`，因此失去系统角色优先级。其他消息的顺序、工具调用、附件及思考字段保留。
- 仅针对启用规则的聊天补全请求。支持自定义 OpenAI 兼容（Ollama 使用 `/v1`）、OpenAI（含反向代理）、OpenRouter。
- 转换成功时，仅关闭**本次请求**的可选提示词后处理，不修改已保存的 API 设置。
- 不支持的消息格式或冲突会整次跳过转换并提示，酒馆继续原流程；原请求仍可能报模型错误。
- 不控制 thinking、预算或截断恢复，不接管工具执行，不支持文本补全路径。

设计参考 Qwen3.6-35B-A3B / Qwen3.5-35B-A3B 官方模板约束，实际酒馆与模型测试由使用者确认，不代表整个模型家族已通过实测。

## 开发验证

Node.js 20 或更新版本，`npm test`。运行时使用原生 ES modules，不需要构建。设计和内部交接文档保存在本地 `.docs/`，不进入 Git。
